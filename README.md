# CS 255 Portfolio – System Analysis and Design

**Johan Tovar**

## Project Overview

The DriverPass project focused on designing a system for a company that helps students prepare for their driving tests. The client wanted a system that would allow students to access practice tests, schedule driving lessons, and manage their appointments. The goal was to make these services more organized and accessible for both customers and employees.

For this project, I created a business requirements document and a system design document. These documents helped me understand how to turn a client's needs into a structured software design.

## What Did I Do Particularly Well?

I believe one of my strengths in this project was identifying and organizing the client's requirements. I was able to distinguish between functional and nonfunctional requirements while considering important details such as system performance, usability, and operating system compatibility.

I also did well comparing process modeling and object modeling. Understanding the strengths of each approach helped me see how they could work together to create a more complete system design.

## What Would I Improve?

If I could revise one part of my work, I would focus on improving the UML diagrams in the system design document. Although the diagrams represent the main system functions, I would add more detail to certain interactions, especially situations involving appointment cancellations, rescheduling, and potential errors.

Including these scenarios would make the design easier for developers to understand and help account for situations that might occur when customers use the system.

## How Did I Interpret and Implement User Needs?

I approached the project by carefully reviewing the client's interview and identifying what the system needed to accomplish. I considered how students, instructors, and administrators would interact with the system and used those requirements to guide my design decisions.

For example, students needed a convenient way to schedule lessons and access practice tests, while administrators needed tools to manage appointments and system information.

Considering user needs is important because software should solve real problems for the people using it. Even if a system works technically, it may not be successful if it is difficult to navigate or does not meet the users' expectations.

## How Do I Approach Software Design?

This course helped me understand that designing software requires planning and analysis before development begins. My approach starts with understanding the problem, gathering requirements, and identifying the users and their goals.

Next, I would organize the requirements and use tools such as UML diagrams to visualize the system's structure and behavior. I would also evaluate functional and nonfunctional requirements to make sure the design addresses usability, performance, and security.

In future projects, I plan to continue using requirement analysis, UML modeling, and iterative improvements. I also want to focus more on identifying possible issues early in the design process instead of waiting until development begins.

Overall, the DriverPass project helped me better understand the relationship between system analysis and software design. It showed me how planning, documentation, and communication contribute to building software that meets both business requirements and user expectations.
